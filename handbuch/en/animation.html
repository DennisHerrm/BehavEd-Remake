Animating movers and ROFF files

Ships, doors and platforms move by keys over time. Store them as move commands in the script, or as a ROFF file - and edit the ROFF files of the game.

Opening the window#

Select a movable entity - func_* brush entities such as func_static ships and func_door, misc_model_breakable, fx_runner - and press Animate in the inspector. If it has no script_targetname yet, it gets one, because a script can only move what has a name.

Keys#

  1. 1

    Put the timeline where the movement starts and press Key at playhead - the first key stores where the entity stands.

  2. 2

    Move on in time and press it again. Then drag the new diamond in the view (Shift: only up and down), or type values into the table: time, position, direction.

  3. 3

    Or simply use the gizmo: while the window shows this entity and the timeline stands at or after the first key, moving or rotating it with the gizmo sets a key at the playhead (or changes the one that is there).

  4. 4

    Delete key and Go to key work on the selected row; Remove animation takes the whole animation out of the script.

Script (move) or ROFF file#

Script (move)ROFF file
Stored asan affect block with move and wait at the start of the scriptscripts/<name>.rof, played by play ( "PLAY_ROFF", ... )

Switch with Script (move) / ROFF file at the top of the window - the keys are converted, nothing is lost. In ROFF mode the field File names the file (for example md_am/roffs/sta2); below it you see how many frames and seconds it has.

How ROFF files work#

A ROFF file (.rof, "Rotation and Origin File Format") stores one small step per game frame: how far the entity moves and turns in the next 50 ms. The game adds these steps to wherever the entity stands when PLAY_ROFF runs - so a ROFF path is relative: move the entity and the whole path moves with it. All 108 files of the game and Movie Duels are version 2, all but one with 50 ms per frame - and that is what BehavEd-Remake writes.

The keys you edit are kept as a comment line in the script right before the play; the .rof is built from them. That is why undo, copy and paste work on ROFF paths like on any command. When you save the script, the file is written to scripts/<name>.rof in the same scripts folder; Save mission packs it into the mission's .pk3.

Editing a ROFF file of the game#

When a script plays a finished ROFF on the entity, the window lists it under ROFF paths of this entity in the script:. Edit turns it into keys - either straight pieces or one smooth curve, whichever needs fewer keys - within half a unit of the original. The game's file is never overwritten: you edit a copy (…_2), and the play command is pointed at it.

In the timeline a ROFF flight is a band under Movement; drag it to start the flight earlier or later.
