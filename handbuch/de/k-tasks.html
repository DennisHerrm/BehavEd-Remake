Warten, bis eine Figur angekommen ist

task, dowait und do: eine Figur ihren Weg beenden lassen, bevor sie sich dreht oder spricht - oder sie zwei Dinge zugleich tun lassen.

Ansicht:

Schritte#

  1. 1

    Warum. Ein affect-Block läuft neben dem Skript her - das Skript wartet nicht auf ihn. Deshalb laufen Kyle und Rosh, jeder in seinem eigenen Block, schon gleichzeitig.

  2. 2

    Das Problem. In einem Block *startet* set ( SET_NAVGOAL ) den Lauf nur; der nächste Befehl folgt sofort - die Figur würde sich drehen oder sprechen, während sie noch läuft. Die Lösung: pack den Lauf in einen task. Füge task ein, nenne ihn walk und verschiebe SET_WALKING und SET_NAVGOAL hinein.

  3. 3

    dowait. Füge hinter dem task dowait ( "walk" ) ein. Es startet den task und wartet, bis er fertig ist - bis die Figur angekommen ist. Alles danach geschieht, wenn die Figur steht.

  4. 4

    Zwei Dinge zugleich. do startet einen task und macht sofort weiter. Zwei tasks - walk und look - werden mit zwei do gestartet, und wait ( "walk" ) wartet später auf den ersten.

  5. 5

    Prüf es in der Zeitleiste. Wechsle zu Mission und klapp die Zeile der Figur in der Zeitleiste auf: was nach dem dowait folgt, beginnt dort, wo der Lauf endet.

  1. 1

    Wo die Befehle sind. Klick in Graph auf einen Skriptknoten (anfangs ist das offene Skript gewählt). Rechts unter Befehle dieses Skripts steht jeder Befehl dieses Skripts - Blöcke eingerückt. Ein Klick auf eine Zeile wählt sie, ein Doppelklick bearbeitet sie, ein Rechtsklick öffnet das Menü.

  2. 2

    Den Task bauen. Klick auf die Zeile affect, doppelklick auf task in der Liste Ereignisse und nenne ihn im Editor walk. Dann klick auf die Zeile task und doppelklick zweimal auf set - für SET_WALKING und SET_NAVGOAL.

  3. 3

    dowait danach. Zieh dowait aus der Liste Ereignisse auf die Zeile task: Ein Befehl, der auf einer Zeile landet, kommt *hinter* sie - hinter den ganzen Block. Nenne den Task im Editor walk.

  4. 4

    In Spuren prüfen. Wechsle zu Spuren: Was dem dowait folgt, beginnt dort, wo der Weg endet.

  1. 1

    Wo die Befehle sind. Spuren zeigt das Skript über die Zeit: die Kamera, eine Zeile je Figur, die Wartezeiten. Rechts listet Befehlsliste jeden Befehl - auch die, die keine Zeit brauchen, etwa affect, task oder declare.

  2. 2

    Den Task in der Liste bauen. Ein task hat keine eigene Zeit - bau ihn in der Befehlsliste: Klick auf die Zeile affect, doppelklick auf task, nenne ihn walk; klick auf die Zeile task und doppelklick zweimal auf set für SET_WALKING und SET_NAVGOAL.

  3. 3

    dowait. Zieh dowait auf die Zeile task der Liste - es kommt hinter den Block - und nenne den Task walk. In der Zeile der Figur beginnt jetzt alles danach dort, wo der Weg endet.

  4. 4

    Zwei auf einmal. Mit do statt dowait beginnt der nächste Befehl sofort - sein Block rückt an den Anfang des Wegs.

Gut zu wissen#

  • Befehle, die in ihrem Hilfetext mit * markiert sind (wie SET_NAVGOAL), beenden ihren task erst, wenn die Aktion fertig ist - genau das lässt dowait warten.
