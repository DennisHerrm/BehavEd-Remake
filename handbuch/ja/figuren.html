マップとシーン

キャラクターと道

キャラクターはナビゴールへ歩き、船は move で飛びます。道全体が見え、マップ上で変更できます。

キャラクターと船の選択#

ビューでキャラクターや船をクリックすると、そのエンティティ(キャラクターのスポナー、船のブラシエンティティ)が選択されます。モデルが動いてもマーカーとギズモが追従し、輪郭線で選択中のものが分かります。キャラクターの矢印はモデルの向きを示します。

始点・終点・新しい点#

  • 終点のハンドルをドラッグすると、歩行の目標(waypoint_navgoal)や飛行の終点が動きます。
  • 始点のハンドルをドラッグすると、線全体ではなく始点だけが動きます。
  • 歩いている途中のキャラクターをつかんで(タイムラインが出発と到着の間)ドラッグすると、その瞬間に新しい点が作られます。キャラクターは新しいナビゴール、船は分割された move になります。
  • 回転も同様です。飛行の途中ではリングが新しい角度の点を作ります。キャラクター(NPC)ではその時刻に set ( SET_DYAW ) を書き、ゲームと同じく旋回速度で向きを変えます。プレイヤーではすぐに向きが変わる set ( SET_ANGLES ) のままです。歩行中は到着時に適用されます。ゲームは歩くキャラクターを進行方向に向けるからです。その瞬間にウォッチターゲットが有効なら、ステータス行が警告します。ゲームではキャラクターがそちらを向き続けるからです。

歩く/走る、共有目標#

歩行の終点ハンドル(またはタイムラインの帯)を右クリックするとメニューが開きます。

  • 歩く(この移動から) / 走る(この移動から) - ナビゴールの前に SET_WALKING または SET_RUNNING を書きます。
  • 歩きながら見る - 歩きながら別のキャラクターの方を向き続けます(SET_WATCHTARGET)。
  • 後ろ向きに歩く(後ろを見たまま) - 始点の後ろに視線マークを置いて後ろ向きに歩かせます。進行方向を向く で解除します。

複数のキャラクターが 1 つのナビゴールを共有している場合、動かすと全員が動いてしまいます。BehavEd-Remake はそれを検知し、先にこの歩行専用の目標のコピーを作ります。どれを作ったかはステータス行に表示されます。

既存のスクリプトの後ろ歩きも認識されます。キャラクターが向きと逆に動くと、ゲームと同じく BOTH_WALKBACK1 または BOTH_RUNBACK1 が再生されます。

キャラクターの動き方 - ゲームと同じ#

プレビューはゲーム自身のルールで NPC をフレームごとに動かします。操舵、移動の物理、経路です。見えているとおりにゲームはスクリプトを実行します。

  • 速さ。 歩行には歩き始めたときの速さが使われます。SET_WALKING・SET_RUNNING・SET_WALKSPEED・SET_RUNSPEED が SET_NAVGOAL の直後にあっても同じです。途中で速さを変えると残りの道のりに適用されます。スクリプトに速さがなければ .npc ファイルの値が使われます。
  • 止まる。 SET_NAVGOAL に NULL を指定するとキャラクターはその場で止まり、その歩行を待つ dowait は先へ進みます。歩行中に新しいナビゴールを指定すると、今いる場所から歩き出します。
  • 向きを変える。 NPC は旋回速度で向きを変えます。毎秒 60 + 3 × SET_YAWSPEED 度です(よくある yawSpeed 90 なら 330 度)。SET_DYAW・SET_VIEWTARGET・SET_WATCHTARGET はなめらかに、SET_ANGLES は即座に向きを変えます。rotate と move は NPC には効きません。ゲームでも同じです。難易度とゲームのルールで一部のクラスの速度が変わります(設定)。
  • 重力。 キャラクターはマップの床に立ち、落ち、段差を上り、斜面に沿い、リフトに乗って動きます。マップの gravity と SET_GRAVITY に従います。マップの読み込み時にスポーンしたキャラクターは、ゲームと同じくカットシーンの開始時にまだ落下中です。DROPTOFLOOR はシングルプレイでは何も変えません。
  • マップのキャラクター。 マップの読み込み時にスポーンするキャラクター(targetname のない NPC_* エンティティ)は、どのスクリプトにも名前がなくてもプレビューに立っています。md_am_sith のアナキンの隣のドロイドがその例です。NPC_Droid_R2D2・NPC_Kyle・NPC_Stormtrooper などのクラスは、ゲームと同じく自分でキャラクタータイプを選びます。ゲームがランダムに選ぶ場合(スポーンフラグなしの NPC_Stormtrooper、Movie Duels のランダムスポーナー)、プレビューは最初の候補を表示します。
  • 経路。 キャラクターが目標へまっすぐ歩くのは、ゲームでもそうする場合だけです。すぐ近く(110 ユニット未満)、隣り合うウェイポイントの間(500 未満)、または遮るもののない直線(400 未満)。それ以外ではウェイポイントのネットワークを点から点へ歩きます。目標をウェイポイントでつないでください(NPC ウェイポイント)。角を曲がる歩行は、同じコマンドの複数の区間として表示されます。
  • 経路がない。 ネットワークに経路がなければキャラクターは立ち止まったままで、その歩行を待つ dowait は終わりません。ゲームでも同じです。ステータス一覧にキャラクターと目標が表示されます。
  • ドア。 ドアなどの動くブラシは、その瞬間にゲームで置かれている位置にあります。NPC は閉じたドアの前で待ち、開くと歩き続けます。ロックされたドア(またはプレイヤーしか開けられないドア)は、閉じている間は道をふさぎます。
  • 段差、曲面、ほかの NPC。 NPC は段差から落ちて着地します。曲面(パッチ)は壁と同じように行く手をふさぎます。NPC 同士はすり抜けません。2 体が出会うと、ゲームがどうすれ違わせるかをプレビューが示し、dowait の時間もそれに従います。
  • BS_NOCLIP。 SET_BEHAVIOR_STATE BS_NOCLIP を使うと、キャラクターはその時点の速さで壁を突き抜けて目標へまっすぐ飛びます。BS_NOCLIP の後に SET_WALKSPEED か SET_RUNSPEED を設定してください。そうしないと、まだ歩いていないキャラクターはまったく動きません(dowait も止まったままになります)。
  • OpenJK か Movie Duels か。 OpenJK のルールでは歩く NPC は 100 ms ごとに進路を直し(上位のセーバー使いは ジェダイ・ナイト 以上で 50 ms ごと)、Movie Duels では 50 ms ごとです。難易度ごとの旋回速度も異なるため、歩行の結果が少し変わることがあります。ルールは 設定 で選びます。

ライトセーバー:壁とぶつかり合い#

ライトセーバーはゲームと同じようにふるまいます。壁・床・ドアに入り込んだ刃は表面までの長さに縮み、また伸びます。触れている間は火花が飛んで音が鳴り、壁に沿って滑った所には焼け跡が付き、少し光ってから 10 秒後に消えます。水中では沸騰します。.sab ファイルに noIdleEffect があるセーバーは、キャラクターが立っているだけの間は静かです。火花・焼け跡・音を出すのはカメラから見えるキャラクターだけです。ゲームもカメラの視野にあるものだけを扱います。タイムラインでジャンプしても、通して再生したときと同じものが表示され、再生位置を後ろへドラッグしても前へと同じく滑らかです。一度計算したものはメモリに残ります(1 シーンにつき最大 10 分)。

2 人のキャラクターの刃がぶつかるのは、ゲームが許す場合だけです。Movie Duels: 両方の NPC が BS_CINEMATIC にあり(set ( SET_BEHAVIOR_STATE, BS_CINEMATIC )、または CINEMATIC スポーンフラグ付きのスポナー)、攻撃側に set ( SET_SABERCOLLISIONS, true ) が必要です。false で再びオフにします。OpenJK には SET_SABERCOLLISIONS がなく、BS_CINEMATIC のキャラクターがアニメーション BOTH_CIN_16 と BOTH_CIN_17 を再生しているときだけ刃がぶつかります(Movie Duels でもこの 2 つは有効です)。当たるとブロックの火花、そのゲームのぶつかる音の 1 つ、クラッシュの閃光が出ます。AI が自分で戦う戦闘(SET_ENEMY、BS_DEFAULT)は再現されず、スクリプトがアニメーションさせるものだけです。Movie Duels では、速い型のセーバーは点火も 2 倍速くなります。ルールは 設定 で選びます。
