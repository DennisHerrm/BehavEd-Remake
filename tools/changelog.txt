## rc587 2026-10-11
[en]
- Script Flow has three views, switched at the top: Classic (the list as before), Graph and Tracks. All three work on the same script and mission - switch any time, edits, selection and undo carry over.
- Graph: the mission as nodes - player start, script runners, scripts, characters, level changes and triggers - joined by what triggers what (target, usescript, deathscript, use, run; affect dashed). Drag from the dot on the right of a node to another node to connect them: behaved sets target, usescript or deathscript, or adds use / run to the script. Double-click opens a script or shows the entity in the map. Wheel zooms, middle or right mouse moves, nodes can be dragged; Fit and Arrange.
- Tracks: the open script over time - camera shots, one track per character, dialogue and the script itself. Click a block to select its line, drag its right edge to change the duration, drag in the ruler to move through time, Play.
[de]
- Script Flow hat drei Ansichten, oben umschaltbar: Classic (die Liste wie bisher), Graph und Spuren. Alle drei arbeiten auf demselben Skript und derselben Mission - jederzeit umschalten, Änderungen, Auswahl und Rückgängig gehen mit.
- Graph: die Mission als Knoten - Spielerstart, Skriptstarter, Skripte, Figuren, Kartenwechsel und Auslöser - verbunden durch das, was was auslöst (target, usescript, deathscript, use, run; affect gestrichelt). Vom Punkt rechts an einem Knoten zu einem anderen ziehen verbindet sie: behaved setzt target, usescript oder deathscript oder fügt use / run ins Skript. Doppelklick öffnet ein Skript oder zeigt die Entity in der Karte. Mausrad zoomt, mittlere oder rechte Maustaste verschiebt, Knoten lassen sich ziehen; Einpassen und Anordnen.
- Spuren: das offene Skript über die Zeit - Kamera-Einstellungen, je Figur eine Spur, Dialog und das Skript selbst. Block anklicken wählt seine Zeile, rechte Kante ziehen ändert die Dauer, im Lineal ziehen bewegt durch die Zeit, Abspielen.
[zh]

## rc583 2026-10-11
[en]
- Multiplayer mode: View > Target game > Multiplayer. The notes then also show what does nothing or works differently on an MP server – camera, print without !, fields MP doesn't know or only stubs, fields that only work on NPCs or players, server crash risks (SET_WEAPON, SET_COPY_ORIGIN, SET_SABERACTIVE), the reversed SET_SABERACTIVE, $get that never returns a value, dowait that never returns, more than 32 variables. Every rule was checked against the MP game code. Thanks to @Seph for the report.
- A misspelled SET_ field in set ( ... ) is now reported with a suggestion (e.g. SET_ORIGNI – did you mean SET_ORIGIN?).
- The original font: BehavEd 2002 uses MS Sans Serif 8 pt everywhere; BehavEd-Remake now uses its TrueType version (Microsoft Sans Serif). Minus signs and dots are easier to see.
- The event editor fits into the window: commands with many fields (e.g. camera PAN) no longer stick out of the window – fields give up their spare width first.
- Compile refuses a script with a line it doesn't understand (e.g. a missing parenthesis) or a block without a closing }, like the original IBIze. Before, such a line was silently left out of the .ibi.
- Opening a script lists every line that wasn't understood in the status bar, with its line number.
- Changelog window (File menu, About window, update window) – in every language.
- Command line: bhed compile no longer writes an .ibi when compiling fails.
